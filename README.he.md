# fitpipeline: סיווג סגמנטים והתאמת פרימיטיבים

[English](README.md)

הכלי מסווג כל סגמנט של רשת משולשים כ-`plane`, `cylinder`, `cone`, `sphere`, `torus` או `unresolved`, מתאים לו את הפרימיטיב שנבחר, וכותב את `predictions.json`. המשימה נמצאת ב-[`assignment/README.md`](assignment/README.md) ופורמט הנתונים ב-[`assignment/DATA_FORMAT.md`](assignment/DATA_FORMAT.md).

## הרצה

דרישות: Python 3.12 ו-[uv](https://docs.astral.sh/uv/). התלויות בזמן ריצה הן NumPy ו-SciPy, ו-pytest משמש לבדיקות. הגרסאות המדויקות נעולות ב-`uv.lock`.

</div>

```bash
uv sync                                               # create .venv with the pinned dependencies
uv run python -m fitpipeline assignment/data predictions.json
uv run pytest                                         # 266 checks, about 35 s
```

<div dir="rtl">

הפקודה קוראת את כל 10 הרשתות, מדפיסה שורה לכל סגמנט, וכותבת את `predictions.json` (הקובץ נמצא ב-repository). הריצה לוקחת כ-2.3 שניות על ליבה אחת. אין בה שום רכיב אקראי, ולכן ריצות חוזרות מפיקות קובץ זהה עד רמת הבייט. דגלים שימושיים:

- `-v`: מדפיס את הנימוק והפרמטרים של כל סגמנט.
- `--mesh mesh_09 --segment 0`: מסנן את הטבלה המודפסת (הקובץ תמיד מכסה הכל).
- `--no-write`, `-q`.

כדי לבחון סגמנט בודד, את הניחושים ההתחלתיים שלו ואת ההחלטה הסופית: `uv run python view.py mesh_08 0`.

אפשר גם בלי uv: ‏`pip install -e .` ואז `python -m fitpipeline ...`.

שני סגמנטי ה-`unresolved`:

- **mesh_09/0** יושב על אליפסואיד עם חצאי צירים 4, 2.5 ו-1.5 (שארית קוואדריקה כללית 3e-8). קוואדריקות שרירותיות מוחרגות במפורש, ולכן הסגמנט נדחה, והנימוק מציין את האליפסואיד.
- **mesh_10/1** לא מתאים לאף פרימיטיב נתמך וגם לא לשום קוואדריקה כללית (שאריות של 10–30% מגודלו), ולכן הוא מטופל כמשטח חופשי (freeform).

## השיטה

השלבים: `loader` ← `geometry` (נרמול) ← `hypotheses` (ניחושים בנוסחה סגורה) ← `refinement` (SciPy) ← `classifier` (קבלה/דחייה ובחירה) ← `predictions` (JSON). כל שלב הוא מודול אחד ב-`src/fitpipeline/`.

### 1. דגימות ונרמול (`geometry.py`)

כל סגמנט מוזז למרכז הכובד שלו לפי שטח ומוקטן כך שההיקף הממוצע (RMS extent) שלו הוא 1. כל החישובים והספים רצים במרחב הזה, ולכן הם לא תלויים במיקום, ביחידות או בכיוון. בסוף התוצאות מומרות חזרה למרחב הקלט.

יש שני סוגי דגימות, ושניהם משוקללים לפי שטח כדי שמשולשים בגדלים לא אחידים לא יטו את התוצאה:

- **קודקודים**, כל אחד במשקל שליש משטח המשולשים הצמודים אליו. ברשת נקייה הקודקודים יושבים *על* המשטח האמיתי, ולכן הם דגימות המיקום.
- **מרכזי משולשים עם הנורמלים שלהם**, במשקל שטח המשולש. הם משמשים לניתוח כיוונים (Gauss map).

### 2. ניחושים התחלתיים בנוסחה סגורה (`hypotheses.py`)

לכל אחד מחמשת הסוגים יש ניחוש דטרמיניסטי, בלי איטרציות:

| סוג | ניחוש |
|---|---|
| plane | PCA משוקלל של הקודקודים |
| sphere | התאמת ספרה אלגברית (לינארית) |
| cylinder | הציר הוא הכיוון הראשי החלש ביותר של נורמלי המשולשים (הם יושבים על מעגל גדול); הרדיוס ונקודת הציר מהתאמת מעגל במישור הניצב |
| cone | הציר מהנורמלים אחרי הורדת הממוצע (הם יושבים על מעגל קטן); הקודקוד הוא החיתוך (ב-least squares) של כל המישורים המשיקים; חצי הזווית מהקודקודים בהינתן קודקוד החרוט והציר |
| torus | כל קווי הנורמל של משטח סיבוב פוגשים את הציר, וזה לינארי בקואורדינטות Plücker; התאמת מעגל בפרופיל (רדיאלי, צירי) נותנת את שני הרדיוסים ואת המרכז |

ניחוש מדולג כשהסגמנט מנוון עבור אותו סוג, למשל אין גליל לסגמנט שטוח.

### 3. פונקציית המטרה (`refinement.py`)

כל ניחוש משופר עם `scipy.optimize.least_squares` (שיטת trust-region reflective). המטרה היא **המרחק הגאומטרי החתום מקודקוד למשטח**, משוקלל לפי שטח:

</div>

$$\sum_i w_i\,\rho\big(d_\text{signed}(x_i;\theta)\big)$$

<div dir="rtl">

פרטים:

- **פונקציית הפסד חסינה:** `soft_l1` בקנה מידה של 0.01 מגודל הסגמנט, כדי שקודקודים בודדים חריגים לא יגררו את ההתאמה.
- **מרחקים חתומים:** למרחק המוחלט יש "שבר" על המשטח, והוא הורס את היעקוביאן המחושב בהפרשים סופיים כשהשארית קרובה לאפס. לכן הפותר עובד עם מרחקים חתומים.
- **פרמטריזציה מינימלית:** כל פרימיטיב מתואר במינימום פרמטרים סביב הניחוש שלו, כך שלאופטימייזר אין חופש מיותר לנדוד בו:
  - כיוונים מוטים בשתי זוויות, כך שהם נשארים וקטורי יחידה;
  - נקודת ציר של גליל זזה רק בניצב לציר;
  - לרדיוסים ולחצי זווית החרוט יש חסמים.
- **תקציב:** עד 200 הערכות של הפונקציה, עם סובלנויות של 1e-12.

כל הסוגים משופרים, לא רק הסביר ביותר. ההשוואה בין שאריות אחרי שיפור היא מה שהופך את הסיווג להוגן.

### 4. סיווג וקריטריוני קבלה (`classifier.py`)

מועמד משופר **מתקבל** רק אם כל התנאים האלה מתקיימים:

| בדיקה | סף |
|---|---|
| RMS משוקלל של מרחק הקודקודים | ≤ 1e-3 × ההיקף הממוצע של הסגמנט |
| מרחק הקודקוד הגדול ביותר | ≤ 1e-2 × ההיקף הממוצע |
| RMS של הזווית בין נורמלי המשולשים לנורמל המשטח המותאם | ≤ max(0.5°, ½ × הזווית הדו-מישורית הגדולה בסגמנט) |
| מספר קודקודים, לסוג מעוקל | ≥ מספר דרגות החופש + 3 |
| רדיוסים | ≤ 1000 × גודל הסגמנט (אחרת המשטח לא ניתן להבחנה ממישור) |

בדיקת הנורמלים חיונית. הקודקודים של גליל גס עם שתי טבעות בלבד (הדפנות הנמוכות של mesh_05) יושבים *בדיוק* גם על ספרה, ורק הנורמלים של המשולשים מבדילים בין השניים. משולש שטוח החסום במשטח מעוגל מוטה בעד חצי הזווית בין משולשים שכנים, ולכן הסף לשגיאת הנורמל נגזר מרזולוציית המשולשים של הסגמנט עצמו.

**בחירה בין מועמדים שהתקבלו:** מישור הוא מקרה גבולי של ספרה ענקית, וגליל הוא מקרה גבולי של חרוט, ולכן לעיתים קרובות כמה סוגים עוברים. המועמדים ממוינים לפי מספר הפרמטרים: plane‏ (3) < sphere‏ (4) < cylinder‏ (5) < cone‏ (6) < torus‏ (7). סוג כללי יותר מחליף את הבחירה הנוכחית רק אם הוא מוריד את שגיאת הנורמל אל מתחת ל-80% מהערך הנוכחי, ובלפחות 0.005°. כך הפרימיטיב הפשוט ביותר שמספיק מנצח.

**אף מועמד לא התקבל ← `unresolved`.** הנימוק מציין את הניסיון הקרוב ביותר. אחר כך מותאמת לקודקודים קוואדריקה כללית $x^\top A x + b\cdot x + d = 0$ ‏(`quadric.py`, נמדדת במרחק Sampson) כדי להסביר את הדחייה:

- **קוואדריקה שלא נתמכת:** אם הקודקודים יושבים עליה, הנימוק אומר איזו, למשל "an ellipsoid with semi-axes 4, 2.5, 1.5".
- **משטח חופשי:** אחרת המשטח מדווח כ-freeform.

האבחון הזה אף פעם לא הופך סגמנט לפרימיטיב.

### 5. פלט (`predictions.py`)

- **`fit.status`:**
  - `fitted`: התקבל, והאופטימייזר עצר על סובלנות.
  - `partial`: התקבל, אבל האופטימייזר מיצה את תקציב ההערכות.
  - `failed`: כל סגמנט `unresolved`. בוצע ניסיון התאמה, ו-`notes` מציין את הסוג הקרוב ביותר. הפרמטרים שלו לא מדווחים (`null`) כי הם לא עוקבים אחרי הגאומטריה.
  - `not_applicable` לא בשימוש, כי תמיד מתבצע ניסיון התאמה.
- **`fit.residual`:**
  - `vertex_rms_distance` ו-`vertex_max_distance` הם ביחידות האורך של הקלט, על קודקודי הסגמנט; ה-RMS משוקלל לפי שטח הקודקוד.
  - `relative_vertex_rms` הוא אותו RMS חלקי ההיקף הממוצע של הסגמנט.
  - `facet_normal_rms_degrees` הוא RMS משוקלל-שטח של הזווית בין נורמלי המשולשים לנורמל המשטח המותאם במרכזי המשולשים.
- **אימות:** לפני הכתיבה נבדק שיש בדיוק רשומה אחת לכל `(mesh_id, segment_id)`, שהערכים המותרים תקינים, שכל המספרים סופיים ושיש עקביות בין `kind` ל-`primitive_type`.

לפי השמות המוצעים ב-`DATA_FORMAT.md`, במרחב וביחידות של הקלט:

| סוג | פרמטרים | הערות |

### משמעות ה-confidence

‏`confidence` הוא ציון היוריסטי בתחום [0, 1], לא הסתברות מכוילת.

- **לפרימיטיב** הוא מכפלה של שלושה גורמים:
  - **מרווח מיקום:** כמה רחוק מתחת לסף נמצאת שארית הקודקודים, בסקאלה לוגריתמית;
  - **ראיות:** מספר הקודקודים ביחס למספר הפרמטרים החופשיים;
  - **הפרדה:** 1 כשאין סוג מתחרה לא-מקונן שגם התקבל. הוא יורד כשמתחרה מסביר את הנורמלים כמעט באותה מידה, ולכן mesh_05/0 מקבל 0.75, כי גם ספרה מתאימה לקודקודים שלו.
- **ל-`unresolved`** הוא עולה מ-0.5 לפי כמה רחוק המועמד הקרוב ביותר מהסף, בסקאלה לוגריתמית. הוא 0.5 כשהדחייה נובעת מחוסר ראיות (מעט מדי קודקודים, שטח אפס) ולא משארית גרועה.

בנתונים הסינתטיים הנקיים האלה כמעט כל פרימיטיב מקבל 0.99, כי השאריות בדיוק של float.

## איך מטופלים קשיים ספציפיים

- **דו-משמעות:** סוגים מקוננים (מישור בתוך ספרה, גליל בתוך חרוט) מוכרעים לפי "הפשוט ביותר מנצח" עם מרווח. זוגות דומים שאינם מקוננים (ספרה וגליל גס) מופרדים לפי הנורמלים, ומורידים את ה-confidence.
- **משולשים בגדלים לא אחידים:** כל ממוצע משוקלל לפי שטח. בדיקה מייצרת רשת שבה גודל המשולשים משתנה פי 10 בערך, ומוודאת שהתשובה לא משתנה.
- **משטחים חלקיים:** כל ההתאמות הן למשטחים אינסופיים ולא דורשות שפה סגורה. קשתות, חרוטים קטומים ופיסות טורוס מותאמים כמו משטחים שלמים, ויש בדיקות על פרימיטיבים חלקיים.
- **כשלים נומריים:** ניחושים מנוונים מדולגים לכל סוג בנפרד. שיפור שזורק חריגה או מחזיר ערכים לא סופיים שומר את הניחוש או מוותר על אותו סוג. סגמנטים עם שטח אפס או מעט מדי קודקודים הופכים ל-`unresolved` עם הנימוק "insufficient evidence", ואף פעם לא זורקים חריגה. לפני הכתיבה נבדק שאין NaN או Inf.
- **שגיאת רזולוציה (tessellation):** השאריות נמדדות על הקודקודים, שיושבים על המשטח האמיתי, וסף הנורמלים נגזר מהזוויות הדו-מישוריות של הסגמנט עצמו.

## בדיקות ממוקדות (`tests/`, ‏266 בדיקות)

- **אי-תלות בתנוחה ובקנה מידה:** כל פרימיטיב מסווג נכון, עם confidence מעל 0.9, תחת סיבוב אקראי עם קנה מידה 0.01, ושוב תחת הזזה ל-1e6 מהראשית. השאריות וה-confidence לא תלויים בתנוחה.
- **דחיית התאמות גרועות:**
  - יריעה חופשית מגובששת יוצאת `unresolved` בכל תנוחה, והנימוק שלה אומר שאף קוואדריקה לא מתאימה;
  - פיסת אליפסואיד יוצאת `unresolved`, וחצאי הצירים שלה מזוהים נכון;
  - ספרה עם בליטה נדחית;
  - סוגים שגויים נשארים התאמות גרועות גם אחרי השיפור.
- **המלכודת של הגליל הגס:** גליל עם שתי טבעות, שהקודקודים שלו יושבים בדיוק על ספרה, עדיין מסווג כגליל.
- **שחזור פרמטרים:** פרמטרים ידועים משוחזרים לכל חמשת הסוגים על משטחים סינתטיים חלקיים, וגם לגליל, לחרוט, לספרה ולטורוס מהנתונים. השיפור מתכנס מניחושים מופרעים ומסיר את ההטיה של הניחוש לטורוס.
- **חוסן:** פונקציית הפסד חסינה מול קודקודים חריגים, משולשים בגדלים לא אחידים, משולש בודד, קלט עם שטח אפס או ערכים לא סופיים, ודיוק רחוק מהראשית.
- **שחזוריות ומבנה הפלט:** הפלט זהה עד רמת הביט בין ריצות והוא JSON תקני ומחמיר, והתנהגות ה-CLI נבדקת.

## מה מומש ומה נלקח מספריות

- **מומש כאן:** כל מה שב-`src/fitpipeline/` וב-`tests/`: הטעינה, הנרמול, הניחושים בנוסחה סגורה, הפרמטריזציות המינימליות, פונקציות המרחק והנורמל, כללי הקבלה, אבחון הקוואדריקה, ציון ה-confidence, כותב ה-JSON וה-CLI.
- **נלקח מספריות:** NumPy לאלגברה לינארית (`eigh`, `svd`, `lstsq`), ‏`scipy.optimize.least_squares` לפתרון הלא-לינארי, ו-pytest.
- **לא בשימוש:** CGAL, ‏Open3D, ‏trimesh, ושום למידת מכונה או גישה לרשת.
- **סיוע AI:** הקוד נכתב בעזרת עוזר קוד מבוסס AI ‏(Claude Code). הצינור לא מבצע שום קריאת AI או רשת בזמן ריצה.

## מגבלות ועבודה שלא הושלמה

- **הספים מניחים נתונים נקיים.** סף של 1e-3 מגודל הסגמנט מתאים לרשתות הסינתטיות המדויקות האלה. על סריקה רועשת כמעט כל סגמנט מעוגל ייצא `unresolved`, והספים יצטרכו להתאים את עצמם לרמת רעש שנמדדת. זה לא מומש.
- **ניחוש אחד לכל סוג.** אין multi-start או RANSAC. ניחוש גרוע בנוסחה סגורה על סגמנט קשה (פיסת טורוס זעירה, חרוט עם חצי זווית כמעט אפס) עלול להתכנס למינימום מקומי ולהידחות. ‏CGAL Efficient RANSAC תוכנן כמחולל ניחושים אופציונלי אבל לא היה נחוץ על הנתונים האלה, ולכן לא מומש.
- **סף הנורמלים מבוסס על הזווית הדו-מישורית הגדולה ביותר בלבד.** קפל חד אחד בתוך סגמנט ירופף אותו לכל הסגמנט, אם כי סף הקודקודים עדיין חל.
- **ה-confidence לא מכויל.** אין נתונים מתויגים לכייל מולם.
- **אבחון הקוואדריקה רק מסביר דחייה.** אליפסואידים והיפרבולואידים מזוהים אבל לא מדווחים כפרימיטיבים, כי הם מחוץ לסוגים הנתמכים.
- **אין כלי ויזואלי.** דוח HTML ב-Plotly תוכנן, ובמקומו יש תצוגת קונסול ב-`view.py`.
