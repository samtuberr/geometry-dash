🔧 The refinement stage

Nonlinear refinement of the PCA/algebraic hypotheses with scipy.optimize.least_squares

Why is a refinement stage needed?

The problem with the hypotheses stage

In the previous stage we built closed-form hypotheses for every primitive:

  • Plane: PCA of the vertices
  • Sphere: algebraic linear least squares
  • Cylinder: a circle in the plane perpendicular to the axis, axis from the Gauss map
  • Cone: an apex estimate from the tangent planes
  • Torus: a circle in the (r, z) profile, axis from Plücker coordinates

These hypotheses are fast and deterministic, but:

⚠️ They do not minimize the geometric distance
  • Torus: facet normals come from chords, not the true surface normal → a bias in the axis
  • Sphere/Cylinder: an algebraic fit, not a geometric one (it minimizes ‖d² − r²‖, not |d|)
  • Cone: the apex from the tangent planes shifts when there is tessellation error

A numerical example: a synthetic torus in a random pose:

Torus seed (hypothesis):
Relative RMS = 4.87e-05

The solution: refinement

After the hypothesis, scipy.optimize.least_squares runs with the hypothesis as its seed. The geometric objective: minimize the weighted sum of squares of the vertex-to-surface distances, weighted by triangle area.

✓ Result:
  • Torus seed 4.87e-05 → torus refined 1.27e-16 (machine precision)
  • Convergence in only 3 iterations
  • Every synthetic primitive converges to machine precision

Optimization techniques

1️⃣ Signed distances (not unsigned)

At first we used abs(distance) everywhere:

❌ Unsigned (a kink at the surface)

distance = |vertex - surface|

The problem: the derivative from the right ≠ the derivative from the left at 0. The numerical (finite-difference) Jacobian breaks down once the residual is < 1e-8.
✓ Signed (smooth)

distance = vertex · normal - offset

The advantage: smooth everywhere. The solver gets an accurate Jacobian and converges to machine precision.

Now: primitives.py has both signed_surface_distance and surface_distance = abs(signed_distance). Refinement uses the signed one; the public scorer uses the unsigned one.

2️⃣ Chart (parametrization)

The parameters of a primitive are not independent: directions must be unit vectors, radii must be positive, and so on. The solver minimizes over a minimal chart (parametrization) around the seed.

Cylinder: 5 parameters θ ∈ [t₁, t₂, t₃, t₄, r] Axis point = origin + t₁·e₁ + t₂·e₂ (slide perpendicular to seed axis) Axis direction = normalized(seed_axis + t₃·e₁ + t₄·e₂) (tilt) Radius = r (bounded: r ≥ 1e-6)

Degrees of freedom:

Primitive DOF Breakdown
Plane 3 normal: 2 tilts (unit), point: 1 (along the normal)
Sphere 4 center: 3, radius: 1
Cylinder 5 axis origin: 2 (across the axis), axis: 2 tilts, radius: 1
Cone 6 apex: 3, axis: 2 tilts, half_angle: 1 (bounded)
Torus 7 center: 3, axis: 2 tilts, R: 1, r: 1

3️⃣ Robust loss

The vertex distances can have outliers (noise, tessellation error). The default is loss="soft_l1" with f_scale=0.01 (1% of the RMS extent).

  • loss="linear": ordinary least squares, sensitive to outliers
  • loss="soft_l1": a smooth approximation of ℓ₁ (Huber-like), resistant to outliers

4️⃣ Normalized frame

As in the previous stage, all computations run in a normalized frame (center = 0, RMS = 1). The result is mapped back to the input frame in the original units. The advantage: tolerances and bounds do not depend on the size or position of the mesh.

API

Entry points

refine_hypothesis(record, hypothesis, loss="soft_l1", robust_scale=0.01)

Refines one hypothesis. Returns a Refinement with initial, refined (Hypothesis), converged, evaluations, message.

refine_segment(record, loss="soft_l1", robust_scale=0.01)

Proposes and refines every primitive for a segment. Returns list[Refinement].

Data classes

@dataclass(frozen=True) class Refinement: initial: Hypothesis # the original hypothesis refined: Hypothesis # the refined hypothesis converged: bool # True if a tolerance stopped it, False if max_nfev evaluations: int # number of residual function calls message: str # scipy's termination message

Real data (43 segments × 10 meshes)

⚠️ An important point: the supplied coordinates are float32, so the natural noise is ~1e-7 in relative RMS. Refinement cannot go below that.
  • Segments that are exactly primitives: converge to ~1e-7 (the float32 noise floor)
  • Segments with tessellation noise: improve after refinement, but not substantially
  • Freeform segments: stay poor fits (RMS > 0.05), as they should
  • Non-convergence: 4 cases (mesh_04, mesh_07, mesh_08, mesh_10) hit max_nfev=200. All of them are a wrong type on a segment of another primitive (for example a plane on a cylinder). The solver does not converge because no good fit exists.

We now have 📊 hypotheses (known and fast) and refinements (more accurate).
The classifier (the next stage) takes both and decides:

  • primitive_type: which refined candidate is best?
  • confidence: how sure it is (based on the relative RMS and the normal angle)
  • reason: a justification (the residuals of all types)

The next stage: the classifier

With hypotheses and refinements we have everything needed to make a decision. The classifier will:

  1. Choose the type: (in the end it does not pick the lowest RMS, but the simplest type that passes both tolerances; see the classifier stage)
  2. Check confidence: are the RMS and the normal angle good enough?
  3. Reject: if every type is poor, mark the segment unresolved
  4. Predict: build predictions.json with fit.status, fit.parameters, fit.notes

There is also a CLI entry point that runs everything end to end over the 10 meshes.

Gotchas and notes

1. Signed versus unsigned distances
The unsigned distance (abs) has a kink at the surface and breaks finite differences. The optimizer uses the signed one; the public scorer uses the unsigned one.
2. The float32 noise floor
The supplied coordinates are float32. ~1e-7 relative RMS is the limit of what can be achieved. No optimization can go below it.
3. Non-convergence for a wrong type
If you refine a cone on the vertices of a sphere, the solver cannot minimize well. It stops at max_nfev=200 with converged=False. That is expected, and the classifier rejects such a candidate on its residuals.
4. Orientation consistency
When a direction vector is refined, it is mapped back to the original frame with parameters_from_normalized. This keeps the relevant sign from the seed.
5. Deterministic and repeatable
No randomness and no random seed. The same segment always gives the same refined parameters, byte for byte.
