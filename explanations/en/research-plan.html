Geometry Fitting Pipeline

Research & Implementation Plan

Recommended Approach

A local Python pipeline built on NumPy and SciPy, with CGAL available for difficult initial guesses, Plotly for inspection, and a small number of coding agents for implementation and review.

The finished program should classify and fit every segment without calling an LLM. This is a compatibility and capability review; we haven't benchmarked these options on the meshes or opened the dataset contents.

CGAL Integration Strategy

⏱️ Time-Boxed Evaluation: 30–45 minutes at the start to test known cones and partial tori, extract usable parameters, and check repeatability. Keep it if it saves initialization work; otherwise use deterministic multiple initial guesses.

Important Note: This workspace currently has Python 3.14.4, while CGAL Linux wheels support only through Python 3.12. A separate Python 3.12 environment is required.

Implementation Considerations:

  • Parameters returned as descriptive strings rather than typed objects—can serve as initial guesses for SciPy refinement
  • Lacks exposed random-seed argument in the reviewed interface
  • A detector finding a convincing subset does NOT establish that the whole segment fits—evaluate entire original segment
  • Reference: CGAL binding implementation

Alternatives Analysis

Alternative Findings Decision
geomfitty Fits planes, spheres, cylinders, and tori, but lacks cones. Cylinder/torus initialization remains caller's responsibility. Reference only
pyRANSAC-3D Published 0.7.0 wheel lacks cone fitting; current repository code adds it. Neither provides torus fitting. Skip as dependency
Easy3D Detects all five types, but wrapper discards sphere, cone, and torus parameters. Skip as fitting backend
PCL (Point Cloud Library) v1.15.1 includes actual torus fitter. Common Python bindings target much older PCL versions. Strong C++ option; unnecessary integration work
CloudCompare / CloudComPy Supports all five primitives and refinement with larger application/plugin environment. Keep as external inspection option
Geometric Tools Provides cone and torus fitters, but uses algebraic objectives; torus initialization sensitive to surface coverage. Useful algorithm reference
MATLAB Localized-Voting Closely matches our task, supports all five primitives. Adding MATLAB or porting would consume timebox. Research baseline; too costly to integrate
Trimesh / point-cloud-utils Useful mesh operations, sampling, and diagnostics. Trimesh can modify indexing. Add only for concrete missing utility
Open3D / PyVista Strong processing and visualization tools. Plotly suits our limited inspection needs with less machinery. Keep as optional tools
Learned Primitive Fitting (SPFN) Supports four types (excluding torus). Published implementation requires older TensorFlow/CUDA setup. Skip for this dataset
Commercial SDKs OptoInspect's API includes all five fits. Access and pricing not established. No purchase before testing open-source

Agent Responsibilities

Use the existing coding environment and assign bounded responsibilities. Do NOT assign an agent to each mesh or segment—numerical fitting belongs in the program, where reruns are reproducible.

💻 Implementation Agent

Loading, fitting code, CLI, output generation, and integration. Primary responsibility for building the pipeline.

🔍 Independent Geometry Reviewer

Cone/torus equations, parameter conventions, ambiguity, and rejection behavior. Provides mathematical verification of implementation.

✨ Optional Documentation Helper

Documentation or formatting based on already verified results. Low-priority support task.

Cost Control Strategies

  • Keep geometry outside model context: Python reads arrays; agents receive compact residual and failure summaries
  • Run one reusable pipeline: Once built, standalone numerical runs consume zero LLM tokens
  • Limit delegation: One implementation agent and one focused reviewer should cover main work
  • Escalate specific failures: Give stronger model a problematic equation or diagnostic, not the whole project
  • Test early on known primitives: Catch initialization and parameter mistakes before tuning against the assignment
  • Keep visualization bound: Plotly HTML—no model involvement
